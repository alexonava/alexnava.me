# Contracts

The interface between the pages, the UI bundle (`src/app.js`) and the deferred scene bundle (`src/scene-entry.js`). The two bundles are built separately and share no module instances (each carries its own copy of `shared/webgl-probe.js`, `shared/motion.js` and `scene/quality.js`); the separate capability worker imports only the shared probe. They meet only on `window.BabelSite`, on DOM ids, classes and attributes, on User Timing names and on build-time defines; neither dispatches a custom event ([Events](#events)). Inside the scene bundle, modules also share a few exports and uniform objects ([Scene module contracts](#scene-module-contracts)), and the framing restates the page's hero breakpoints ([Hero breakpoints](#hero-breakpoints)). A contract changes on both sides, with its test ([Testing](TESTING.md)), in one commit. [Architecture](ARCHITECTURE.md) describes what each module does; this page lists what they promise each other. Terms such as live path, static path, startup tier, asset tier, reveal, film and text guard are defined in the [Glossary](GLOSSARY.md).

## Load order

1. `index.html` loads the UI bundle with `<script defer src="/scripts/app.js">`. [app.js](../src/app.js) imports, in order: `shared/webgl-probe.js`, `shared/motion.js`, `scene/quality.js`, `ui/hero.js`, `ui/contact.js`, `ui/scene-loader.js`, then `main.js`. Each is an IIFE that registers on `window.BabelSite`.
2. [main.js](../src/main.js) runs `initUi()` at `DOMContentLoaded` (or at once if the document has parsed), then, after first paint, the static gates. Eligible visits await `shared.prepareWebGLCapabilities()` and recheck preferences afterward. Its one-shot [worker entry](../src/webgl-probe-worker.js) imports the shared probe into its own scope and posts the capability object; the UI validates and caches it, then terminates the worker. Worker failure or no worker WebGL falls back to the document probe. On the live path main.js appends the scene entry as `<script type="module">`.
3. The scene entry's static import, the shared Three.js chunk, evaluates first. [scene-entry.js](../src/scene-entry.js) then imports `perf-marks.js`, `shared/webgl-probe.js` (which keeps the UI bundle's cached probe), `shared/motion.js`, `helpers.js`, `palette.js`, `world.js`, `textures.js` and `index.js` (which imports `quality.js` again and the rest of the scene), and marks `babel:scene-entry`. The build refuses a first-party module in the shared chunk because it would evaluate before this order ([Troubleshooting](TROUBLESHOOTING.md#the-build-fails)).
4. main.js calls `BabelSite.scene.initHomeScene()`.

## window.BabelSite

Each module that registers on it creates the object if it is missing (`window.BabelSite = window.BabelSite || {}`), so it exists from the first module on; its members depend on load order. "UI bundle" in the Exists column means from the moment `/scripts/app.js` evaluates (a deferred script, before `DOMContentLoaded`); "scene bundle" means from the moment the scene entry evaluates, on the live path only.

quality.js publishes `SCENE_QUALITY_PROFILES`, `createSceneQualityGovernor`, `createSceneQualityState`, `detectSaveData`, `getSceneCompositionProfile`, `getSceneQualityProfile`, `qualityCapsFromProbe`, `readSceneQualityControls`, `readWebGLQualityCaps`, `resolveEffectiveDprCap` and `selectSceneQualityTier`.

A `maxTextureSize` of 0 means the probe could not read the limits. `qualityCapsFromProbe()` then returns `null`. Without a `?quality=high` or `balanced` override main.js leaves the startup tier unknown (and makes no early request); with or without one, the scene opens one more WebGL context of its own (`readWebGLQualityCaps()`) to read the limits.

`scene.prefetched` holds the startup tier's tree request and, for a resolved tree opening, its optional lantern request. Tree openings request tree then lantern at high priority; Watch openings request tree at low priority. main.js creates it after requesting the scene script, only when the startup tier is known, `__BABEL_ARCHITECTURE_PREFETCH_URLS__` is defined and `fetch` and `AbortController` exist; a hidden page waits until it is shown, and a page that is shown only after the bundle has run makes no early request. architecture-assets.js takes a matching entry at most once (deleting it), and aborts and clears the rest when the live selection starts or the controller is disposed. If a static preference interrupts startup, main.js keeps already-started responses for the next eligible attempt and cancels deferred visibility prefetch; that attempt reuses the loaded entry and restarts its loading line. Ordinary bundle or initialization failures abort and clear the requests. The map is absent on an initial static path and when the startup tier is unknown.

`initHomeScene()` returns `false` without a `#home-scene` host, without WebGL, or when its own startup tier is low, and `true` once the scene is running. A throw during initialization disposes what registered and rethrows; main.js then reports `Scene bundle failed to load.` and hides the host. After disposal `setVisitorPaused` and `isVisitorPaused` return `false` and `disposeHomeSceneRuntime` does nothing.

**Inputs set before the scene loads.** A script that runs before the scene bundle may set `BabelSite.scene.visitorPausedPreference = true` (the scene then pauses at the reveal and keeps its first revealed frame), and `scene.cinematicSelection` and `scene.cinematicAngle` (0-based) to choose the opening shot without URL parameters; UI boot and index.js pass them to the same pure `resolveSceneOpening(search, { view, angle })`. Script subjects select their first shot when no angle is supplied, and a valid zero-based script angle overrides the public angle. Invalid script values resolve to the same first-shot fallbacks. With neither explicit public selector nor script override, the result is `{ view: "tree", angle: 1 }`, Lantern study. The loading line, early requests and renderer use that result together.

## Hero breakpoints

The directed camera frames each shot by where the hero sits, which styles.css decides by media query. [directed-shots.js](../src/scene/directed-shots.js) restates those breakpoints in `isStackedLayout()` and `resolveDirectedShot()`, and [cinematic.js](../src/scene/cinematic.js) `cinematicSafeArea()` frames by them, so a change to the hero's breakpoints changes the code too, with [cinematic.test.mjs](../test/cinematic.test.mjs) and [framing.test.mjs](../test/framing.test.mjs). Widths and heights are the scene's size in CSS pixels; "portrait" includes squares, as CSS's `orientation: portrait` does.

| Viewport                                                               | Hero (styles.css)                                                                         | Subject framed (`cinematicSafeArea`)  | Shot variant (`resolveDirectedShot`)                                                                              |
| ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Portrait up to 760px wide                                              | `(max-width: 760px)`: tops the screen                                                     | Below the name (stacked)              | `portrait`                                                                                                        |
| Portrait 761–1024px wide                                               | `(min-width: 761px) and (max-width: 1024px) and (orientation: portrait)`: tops the screen | Below the name (stacked)              | `portrait`                                                                                                        |
| Taller than wide, over 1024px wide (portrait monitors)                 | No query: bottom-left                                                                     | Across the full width, above the name | `portrait`                                                                                                        |
| Landscape up to 500px tall, at any width                               | `(orientation: landscape) and (max-height: 500px)`: top-left                              | Right of the hero                     | `squat` or `portrait` narrower than 1.55:1 (`SQUAT_LANDSCAPE`), else `compact` under 600px wide, else `landscape` |
| Landscape under 600px wide and over 500px tall                         | `(max-width: 760px)`: tops the screen                                                     | Below the name (stacked)              | `portrait`                                                                                                        |
| Landscape 600–760px wide and over 500px tall                           | `(max-width: 760px)`: tops the screen                                                     | Right of the hero                     | The shot itself                                                                                                   |
| Landscape over 760px wide and over 500px tall, and squares over 1024px | No query: bottom-left                                                                     | Right of the hero                     | The shot itself                                                                                                   |

`isStackedLayout(width, height)` is `true` for the three stacked rows: `height >= width ? width <= 1024 : width < 600 && height > 500`. A shot without the chosen variant keeps its own framing ([Scene modes](SCENE-MODES.md#viewport-variants)).

## User Timing

Every scene name starts with `babel:`. Marks and measures are best effort: without User Timing nothing is recorded and nothing fails ([perf-marks.js](../src/scene/perf-marks.js)).

| Name                   | Entry   | Emitted by             | Covers                                                                                                                      |
| ---------------------- | ------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `babel:scene-request`  | mark    | main.js                | The scene script's request; with `babel:scene-entry`, both chunks' download and Three.js evaluation                         |
| `babel:scene-entry`    | mark    | perf-marks.js          | The start of the entry chunk's evaluation, after the shared Three.js chunk evaluated                                        |
| `babel:scene-eval`     | measure | perf-marks.js          | The entry chunk's evaluation, excluding Three.js                                                                            |
| `babel:init`           | measure | index.js               | `initHomeScene()`                                                                                                           |
| `babel:first-frame`    | measure | index.js               | The first frame that draws, at or before the reveal                                                                         |
| `babel:reveal`         | mark    | index.js               | The first frame shown                                                                                                       |
| `babel:glb-parse:ROLE` | measure | architecture-assets.js | Parsing a model: `tree`, `lantern`, `lichen-rock`, `weathered-stone`, `mountain-ridge`, `mountain-spine`, `mountain-summit` |
| `babel:assembly:ROLE`  | measure | index.js               | Committing the `watch` or assembling the `tree`                                                                             |
| `babel:shaders:LABEL`  | measure | index.js               | A shader warm-up, request to settle: `scene`, `ground`, `mountains`, `watch`, `tree`, `lantern`, `opening`                  |
| `babel:ground-paint`   | measure | textures.js            | Painting the procedural ground canvases                                                                                     |

Consumers:

- scene-loader.js observes marks and measures with a `PerformanceObserver`. The `babel:reveal` mark ends a run as revealed (backing up the `is-ready` class change); the measures matching `babel:(glb-parse|assembly|shaders):(watch|tree)` fill the build share of the line. Other names are ignored.
- terrain-build.js and mountain-build.js read the latest `babel:reveal` mark's `startTime`, with the host's `transitionDuration`, to tell whether the canvas is still fading in.
- The browser's Performance panel and Lighthouse's User Timing audit group the entries by the prefix.

## Scene loader

`BabelSite.sceneLoader` is the API of the loading line and its star. Every method is wrapped so it never throws into its caller.

| Method                  | Caller                                                              | Contract                                                                                                                                                                                                                                                                                                                                                                      |
| ----------------------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `begin({ tier })`       | main.js, on the live path, before the scene script                  | Starts a run; ignored while one is loading. Shared URL and script opening resolution supplies the watch plus the tree for a tree opening.                                                                                                                                                                                                                                     |
| `stage(name)`           | main.js                                                             | `"bundle"` once the scene script has run, `"init"` once `initHomeScene()` returned `true`.                                                                                                                                                                                                                                                                                    |
| `preparation(snapshot)` | index.js; optionally `babel:opening-preparation` on window          | `{ status, completed, total, stage, reason }`, with status `preparing`, `ready`, `fallback` or `failed`. Reports count only while a run is loading, so one after the line has ended changes nothing. A revealed line's star stays under the canvas and hides with the line 600 ms later; a retired line hides it at once.

## Status objects

### Opening preparation

`resolveSceneOpening(search, { view, angle })` in scene-modes.js is renderer-independent. Its returned angle is zero-based; public `?angle=` remains one-based. No public selectors defaults to Lantern study (`tree`, 1). An explicit valid subject with no valid angle selects its first shot, an unknown explicit subject or bare public angle retains the Watch fallback, and a validated script override wins. UI boot maps `scene.cinematicSelection` and `scene.cinematicAngle` to those override fields before the scene entry arrives.

`cameraTour.nextShot` observes the actual upcoming available `{ subject, angle, name, shot }`, recomputed from the current lists so coastal mounting or withdrawal cannot leave a stale target. `update({ ready: false })` holds tour time during startup. `reset()` clears dwell and transition state without choosing a different subject or angle; reveal uses it to grant the opener its complete native hold.

`createOpeningPreparation({ stages, idleMs, totalMs, report, fail })` owns readiness independently of the decorative UI. `settle(stage)` records a stage once, `reopen(...stages)` invalidates completed work after a pre-reveal camera or viewport refit, `tick(timestamp, visible, progress)` charges visible preparation time and accepts increasing real download or completed build-work progress as an optional heartbeat, and `dispose()` prevents later transitions. Defaults are 15 s without progress and 30 s total visible preparation. main.js starts the independent opening clock before capability preparation and module loading, races pending capability and entry/shared-module work against expiry, and installs the internal `scene.takeOpeningBudget()` handoff. That method charges time through synchronous setup, stops the pre-entry observer and returns the remaining milliseconds for the scene gate's `totalMs`; the phases share one 30 s budget. Hidden documents and blocking static preferences pause the clock, and preference recovery retains consumed time. Bundle completion is genuine progress. A pre-entry expiry releases unused prefetched models and deferred visibility work and marks the attempt terminal, so a late module cannot initialize through `ensureSceneReady()`. Close tree openings require subjects, settled supplied or fallback lantern, terrain, materials, root/bank details, full current-move foreground, rocks and final shader preparation; the Watch path requires subjects and shaders. The lantern's 8 s optional-asset deadline calls `architectureAssets.cancelOptional("lantern")`, restores the stand-in and releases the cancelled channel's leases; late assets remain stale and are released. It never changes the 6 s Lantern study dwell. Failure hides the canvas, retires the loading line and disposes the pending runtime after bounded program work settles. The loader's separate `babel:opening-timeout` event reports `{ reason: "idle" }`; losing that decorative listener or the line itself cannot disable the functional deadlines.

main.js imports the pure opening factory once and lends that exact function through the internal `site.shared.createOpeningPreparation` bridge. The deferred scene reuses it; a missing or invalid bridge makes initialization return `false` before constructing a renderer. The shared WebGL capability object is preserved. This factory creates independent local gates and adds no control over the running scene.

Shader preparation requires successful linking, not just completion. `shader-programs.js` polls captured parallel programs before checking their native `LINK_STATUS`; a failed diagnostic, retired handle, context or generation cannot report ready. This also works when production disables Three's lazy diagnostic logging. The internal rendering `programsLinked()` uses the same check after the serial backend's existing hidden draw, with no extra render pass or serial precompile. Either backend keeps the title card when a required program fails.

`BabelSite.sceneDebug` exposes observations rather than controls, and `BabelSite.sceneLoader.state` returns a fresh snapshot; changing these observations cannot control the scene. The independent preparation gate can observe loader progress and the monotonic hidden-work counter as optional heartbeats, while its own stage and deadline logic still works without the UI. `settleRoots()` returns the prepared sampler published by `filmScene.ready`. Calling it samples the visible ground: procedural ground until landing and while film is withdrawn, otherwise the root-supported coastal terrain. Its `shore(x, z)` likewise returns `Infinity` until landing and while withdrawn. The walk retains this delegated sampler, but index.js permits entry only while its shore distance is finite, including after reactivation; a missing or failed sampler never enables expanded walking on the procedural fallback. Its internal `film(x, z)` always samples the prepared film terrain. rock-build.js starts both GLB loads immediately, owns completed assets while awaiting the sampler's `ready`, and selects `film` for permanent placement so later film deactivation cannot change its height. Its internal `setActive()` controls withdrawal and relanding; `ready` resolves `true` at the first commit or `false` on disposal before commit. A false result frees the loaded rocks without placement; disposing the rock owner frees them even while coastal readiness is pending.

`createEarthGeometry()`'s sixth argument, `prepareOnly`, is internal to film-scene.js when `settleRoots` is available: the detached sliced build resolves on preparation completion, leaving publication and shadow invalidation to the atomic owner. With a real `rendering.homeScene`, `preparedEarthSteps()` also drains ocean.js `coastGeometrySteps(height, tier, drop)` through the existing `inSlices()` scheduler before resolving. Its cliff-column and stack-row yields preserve the synchronous builders' exact buffer bytes. The terrain owns `geometry.userData.coastGeometry`, an internal `{ cliff, stacks, tier }` record; its disposal clears and frees any unconsumed buffers. `createCliff({ prepared })` uses those exact buffers and the recorded tier, then nulls the two fields only after the complete shore owner exists, transferring disposal once. Cancelling the generator releases partial or completed buffers it has not handed off. Without prepared buffers, `createCliff()` retains its synchronous builders. Default terrain callers and the missing-settler fallback retain the existing unseen publication gate and shadow invalidation. This preparation starts no map, shader or draw.

`settleRoots()` lends the ground's material to `createCliff()` for the cliff geometry's shelf group. The shelf has the terrain's UV phase and neutral root attributes, so the same material supplies its current maps, close soil and lighting through replacement or fallback. The lip/face group and the stacks retain the cliff owner's rock material. This adds one draw in the existing scene pass and reuses the ground's program and adds no effect pass. The cliff owner requests two independent optional rock textures after reveal: sRGB albedo through `createCoastAlbedo()` and packed normal/roughness detail through `createCoastDetail()` (both in coast-detail.js). Each has its own staging, bounds and procedural fallback; either can succeed without the other. The cliff never changes or frees the borrowed ground material or its textures. Without a lender the standalone cliff retains its single rock material.

`film-light.js` owns the shared `COAST_MOOD` scalar. The bootstrap writes the current shot's `light.coastStudy`, default zero, and `film-scene.js` lends the same uniform through the terrain library to the shore materials and the ground material's existing `coastRockUniforms` owner. `shadeSlatePuddles()` borrows it as `slateCoastStudy`, defaulting to zero without a lender; the existing material commit, withdrawal and restoration lifecycle remains responsible for the binding. Only the three coastal studies select their refined mineral, ripple, aeration and spray response. Their ground and falling head use the same world rapids frame, physical radius, gradient and brink crest over the existing fourteen-unit support. `RAPIDS_BODY` supplies their common clear-water albedo; the body reconstructs the ground's existing legacy-light balance from its borrowed raw lights and existing pool-light lookup. The toe and pool share diffuse coverage at the landing line; within that same toe window the body's single existing shadow lookup approaches the sea-level, up-facing pool datum. A lower, smaller airborne spray core leaves the landing exposed. River/channel geometry, current clocks, textures, lights and passes remain unchanged. Lantern study, other tree views and the walk keep the established profile-zero response; switching the borrowed scalar adds no program variant.

`createCoastDetail()` belongs only to the lazy cliff owner. `setActive()` and `setRevealed()` gate its one optional request; `take({ revealed, running, cut })` applies staged detail only on a cut or a still frame. `applyQuality()` keeps the same startup asset. The loader bounds its body to 48 KiB and its request to 8 s, and requires 256×256 pixels. Decode uses no colour conversion and flips the bitmap once; the texture is `NoColorSpace`, `RepeatWrapping`, mipmapped and not flipped again. Red/green carry OpenGL normal X/Y without green inversion, blue roughness, on a 6.56-unit tile. Withdrawal resets the binding and cancels pending work; a complete texture and bitmap stay cached through reactivation and context restoration. Failed requests retain procedural shading without automatic retries. `dispose()` restores the binding before freeing the owned texture and closing its bitmap, and never frees the shelf's borrowed material or maps.
