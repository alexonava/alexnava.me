# Architecture

## Overview

alexnava.me is a static site: two pages, one stylesheet, a small UI script and a deferred Three.js scene, built by esbuild into `dist/` and served by Cloudflare Pages. The page never depends on the scene. The title card (a night sky drawn in CSS, the identity and Contact) is the first visual, and it is final for static visitors. Capable devices load the scene behind it, reveal it once it can draw, and tour five directed shots, the painted sky (The watch) and a twisted tree with a lantern, joined by three coast shots when the lazy sea and cliffs land. Terms such as film, baseline, startup tier, low tier, commit point and stand-in lantern are defined in the [Glossary](GLOSSARY.md).

The UI and scene bundles meet only on `window.BabelSite`, a few DOM hooks and the scene's `babel:` User Timing entries, which the loading line observes. The UI publishes `BabelSite.ui`, `BabelSite.shared`, `BabelSite.sceneLoader`, `BabelSite.ensureSceneReady` and the quality helpers on `BabelSite.scene`. The scene entry adds its own entries to `BabelSite.scene`, among them `initHomeScene`, `setVisitorPaused` and `isVisitorPaused`, and publishes `BabelSite.sceneDebug` when asked. [Contracts](CONTRACTS.md) lists every shared name, event, attribute and User Timing entry. `Babel` is the code's own namespace (`BabelSite`, the `babel:` marks and events, the `__BABEL_*__` build-time defines), not the Babel compiler.

## Page and startup

[src/main.js](../src/main.js) boots in this order:

1. `initUi()` wires the hero (`initHeroChrome()`) and then the footer's Contact (`initContact()`, [contact.js](../src/ui/contact.js)): Contact shows, the email address and LinkedIn fold behind it, and an address ending `#about`, `#profile`, `#experience` or `#contact` (or the same with `-text`) opens them ([UI](UI.md#contact)). Neither waits for the scene.
2. After first paint (`requestIdleCallback` with a 500 ms timeout, or `requestAnimationFrame` then `setTimeout` without it) it applies the static gates. Forced colours are checked first: while active, the scene host is hidden without probing WebGL, requesting the scene bundle or models, or starting the loading line. Neither a quality override nor `?sceneDebug=1|true` bypasses this gate. The scene also stays static when reduced motion or reduced data is preferred (including `navigator.connection.saveData`), when WebGL is unavailable or software-rendered (SwiftShader, llvmpipe, Microsoft Basic Render Driver), or when the startup tier is low. `?quality=high|balanced` passes the reduced-motion, reduced-data and software gates. `?sceneDebug=1` passes the same three in main.js, but a reduced-data preference still gives the low startup tier (quality.js `selectSceneQualityTier`), so the title card stays: main.js declines before requesting the scene bundle or, when the probe could not read the texture limits, after downloading it, once `initHomeScene()` declines the low tier. Neither passes the WebGL gate, and `?quality=auto` or an unknown value forces nothing. There is no user-agent, Lighthouse or viewport exception. When forced colours clear, main.js rechecks the remaining gates even with an explicit quality or debug override, starting the scene once if eligible; concurrent recovery events share the startup already in flight. Without an explicit quality or debug override, clearing reduced motion or reduced data also rechecks startup. An explicit `?quality=high|balanced|low` or `?sceneDebug=1|true` determines startup as above (`forcesLiveScene`); clearing motion or data alone does not trigger recovery from a static tier selected under those controls.
3. The startup tier comes from [quality.js](../src/scene/quality.js), which the UI bundle carries, and the limits the WebGL probe already read. Unknown limits leave the choice to the scene, which reads them with a probe of its own and declines the low tier itself (`initHomeScene()` returns `false`).
4. `sceneLoader.begin({ tier })` starts the loading line. main.js appends the scene entry as a module script and, just before it, a `<link rel="modulepreload">` for each chunk the entry imports statically (`__BABEL_SCENE_MODULE_PRELOADS__`: the shared Three.js chunk), so both download together. No lazy chunk is preloaded.
5. It then requests the startup tier's tree at low fetch priority (`__BABEL_ARCHITECTURE_PREFETCH_URLS__`; a hidden page waits until shown) and shares the responses on `BabelSite.scene.prefetched`, keyed by URL. [architecture-assets.js](../src/scene/architecture-assets.js) takes a matching response at most once; the rest are aborted when the live selection starts, at teardown, or when the bundle or initialization fails.
6. When the bundle has run, main.js reports `stage("bundle")`, calls `initHomeScene()` and reports `stage("init")`. A failed bundle or initialization hides the host and calls `end("static")`. A failed module load removes its script so a later call can retry.

The capability gate calls `shared.prepareWebGLCapabilities()`. When Worker and OffscreenCanvas are available, a one-shot, fingerprinted same-origin worker runs the shared probe, reads the same renderer and texture limits, and releases its context. A missing, blocked, malformed or timed-out worker (2 s) falls back to the document canvas probe; a worker reporting no WebGL also falls back, since worker support does not establish document support. The result is cached for the scene's synchronous guards. main.js rechecks preference gates after the asynchronous probe before requesting any scene asset, after the bundle downloads, and before initializing an already-loaded entry. A preference that interrupts startup rearms recovery: the next eligible change reuses the downloaded entry and already-started model responses, with no duplicate startup. Deferred hidden-page prefetch is cancelled; ordinary bundle or initialization failures do not install an automatic retry.

### Title card and loading line

Neither page has an `<img>` or `<picture>` element, and the stylesheet requests no image: its only URLs are the fonts and `data:` URIs (the night's stars, the grain and the cursor). index.html and styles.css paint the title card: the night gradient, a CSS star field (`.scene-shell::before`) and the vignette under the identity and Contact. A faint grain (`.scene-vignette::before`, a 150px inline SVG tile) dithers the night against banding. It fades with the canvas's reveal through a sibling selector, `.scene-canvas.is-ready + .scene-vignette::before`, so the vignette must directly follow the scene host ([Contracts](CONTRACTS.md#dom)). The 404 page is the same CSS night with one centred line: the eyebrow, a heading in the name's type, a sentence in the intro's and Home in the footer's; it has no scene host, so its grain stays. Its head names the homepage's icons, preloads both fonts, declares `color-scheme: dark` and takes the site's description. It loads no script.

On the live path [src/ui/scene-loader.js](../src/ui/scene-loader.js) (`BabelSite.sceneLoader`) shows one line, `#scene-loader`: a label above the footer and a bar along the window's top edge, both in the name's colour ([UI](UI.md#loading-line)). Its value is real progress, as the label's percentage and as the bar's fill (`scaleX()` of the same value): 10% bundle, 4% initialization, 70% model bytes and 12% build, a running maximum held at 96% until the reveal; with no model to download (the default view, the watch) the build takes the bytes' share, 82%. Bytes count the required models (the tree, for `view=tree`): `track(url, response)` reads each model response into a copy as it arrives and counts decoded bytes against the sizes build.mjs defines for the UI (`__BABEL_ARCHITECTURE_PREFETCH_BYTES__`). Build follows the scene's measures `babel:glb-parse:<role>`, `babel:assembly:<role>` and `babel:shaders:<role>` for the watch (assembly and shaders: it parses no model) and, with `view=tree`, the tree. A MutationObserver on `#home-scene` ends the run: gaining `is-ready` is the reveal (100% and a full bar, then the line fades within the canvas's fade-in), and `hidden` retires the line below 100%. The `babel:reveal` mark, seen through a PerformanceObserver, also completes it. A watchdog checks every 2 s, completes the line once the host is `is-ready`, and retires it as stalled once 15 s (`STALL_MS`) pass without progress, which its checks reach at 16 s, counting only time while the page is visible. The watchdog does not check the host's `hidden` attribute: without a MutationObserver, a host the scene hides after a failed watch or tree retires the line only through that stall. `.scene-canvas` keeps one 480 ms opacity transition; terrain-build.js and mountain-build.js read it as `transitionDuration`.

The line's star, `#scene-star` in the scene shell, stands where the opening shot will show the scene's star (the owner's rule: it has to line up), under the canvas. The scene reports that place through `sceneLoader.star()` in CSS px from the canvas's top-left: index.js `reportLoaderStar()` converts a `lensSource()` result (canvas UV, y up, the radius in frame heights) with the renderer canvas's `getBoundingClientRect()` size. Before the watch commits, `predictLoaderStar()` reports [opening-star.js](../src/scene/opening-star.js) `openingStar()`: from the scene's start (in `applySceneSize()`, once the composition has set the scene's height through `subsystemRegistry.resize`), again on every resize and once the fonts load, until the camera's own report or the reveal. `openingStar()` fits a cinematic camera of its own (cinematic.js `createCinematicCamera`'s `measure` option) to the watch's stored outline ([opening-outline.js](../src/scene/opening-outline.js), opening-star.js `watchMeasure()`, which the scene's camera frames The watch by too) for the asset tier and The watch's resolved variant, with the scene's safe area (`cinematicArea` or `measureCinematicArea`), its ground (`cinematicGroundY`, which the scene's camera reads too), the star's world position and the watch's marker (`watchRoot`, where the lookout's posts stood on the terrace, its world height `watchY`, so the environment root's composition height lifts or lowers it); it applies The watch at time 0 and the tour's opening phase (`cameraTour ? 0 : null`) and projects the star with `lensSource()` before disposing the controller, whose disposal resets the camera's lens. It takes about 0.2 ms, and gives no star when the opening is another shot (anything but the watch's angle 0, from `scene.cinematicSelection` and `cinematicAngle`), the outline is missing or stale for that tier and variant, or the star stands outside the frame. Measured on 30 window shapes (desktops from 1280×720 to 3440×1440, a square, squat windows 560–700 px wide, portrait monitors, phones both ways and tablets), the prediction lands within 0.56 px of the camera's own star. Once the scene's camera has fitted the opening shot itself, the lens block computes the star from the live camera while the canvas is not yet shown and reports that instead (`openingCameraStar`), until the reveal. scene-loader.js warms the star with the real progress, from the progress at which its place first became known to the reveal ([UI](UI.md#loading-lines-star) has the parts and their transforms), writing only transforms and opacities, at most once a frame. At the reveal the line reads 100% and the star is the scene's own as the opening shot shows it, in place and size; the canvas fades in over it, and it hides with the line after 600 ms. A line retired below 100% hides its star at once, and reports after a run has ended are ignored.

`node tools/bake-root-shade.mjs` prints the three constants from both tree variants, deterministically; paste them over the ones in [terrain-build.js](../src/scene/terrain-build.js) whenever one of its inputs changes: the tree models, the tree's seating (`TREE_FOOTING`, `TREE_SINK`), the root lines and lattice, the key-light direction (`KEY_LIGHT`), the lantern's flame (`LANTERN_FOOT`, `LANTERN_IMAGE.glow`), the terrain, or the ground the tables must leave untouched (the lantern clearing about `LANTERN_FOOT`, the river to its reach (`RIVER`, `RIVER_BED`, restating `SLATE_RIVER` and `SLATE_RIVER_BED` in mud-ground.js) and the puddles in `PUDDLE_ZONES`), or the stream's channel (`STREAMS`, restating `SLATE_STREAMS`). `test/terrain-build.test.mjs` re-bakes and fails on any difference.

[opening-outline.js](../src/scene/opening-outline.js) is data, never edited by hand: The watch's stored outline, baked from the lookout's models before the owner left the lookout out (2026-10-20) and kept, so The watch frames as it was composed. For every variant `resolveDirectedShot()` gives The watch over a sweep of window sizes (three today, each keyed by `outlineKey(shot)`: its subject, region, focus, azimuth, height and target height, everything `measureShot()` reads from a shot) it holds each tier's measurement of the lookout (high and balanced), its root at the origin, its points reduced to their convex hull: `fitShot()` tests each point only against linear limits, so the hull fits exactly as all the points do. The tiers fit a few px apart in some variants (short landscape windows), so each tier has its own. Points are stored as little-endian Int16 multiples of `OUTLINE_RESOLUTION` (0.005 world units), base64: about 9.7 kB of source, 4.7 kB gzipped, in the scene's default load. A change to The watch's framing (`DIRECTED_SHOTS.watch[0]` and its variants) that changes a key finds no outline: `test/opening-star.test.mjs` holds every variant of The watch to an entry for both tiers.

The film's ground work also prepares before publication. `environment.prepareFilmDetail()` builds detached grass during model downloads through the same seeded generator used by the immediate constructor; the watch waits for it, and film activation only adopts the finished detail. Normal accumulation and bounds run in short slices with the same buffer results. After terrain settlement, optional root litter and rushes build detached in idle slices, free partial geometry on cancellation and join only at existing unseen commit points. Procedural ground canvases start as a small flat preview; full detail is painted only for a failed slate load, a reset out of film, or a visible frame that still needs the procedural maps. Successful slate loads skip that unused painting.

The Python material helpers are offline authoring tools, never build or runtime requirements. `python tools/bake-coast-albedo.py --source PATH --output images/materials/coast-albedo-512.webp` requires the known diffuse source MD5, uses Pillow locally and prints the final WebP's measured linear RGB mean for `COAST_ALBEDO.mean`. [Assets](ASSETS.md) and [Credits](CREDITS.md) describe their source and format contracts.

`python tools/repair-landmark-geometry.py --source-dir PATH --output-dir images/architecture` reads the two original tree GLBs and verifies their SHA-256 hashes. It computes the bounded fork-volume change and affected surface frames, verifies every approved output hash in memory, and then writes the two results; optional `--report` records the checks. Local NumPy is its only authoring dependency. Model lengths, JSON, maps, UVs, indices, AABBs and protected contacts stay fixed; runtime code performs no repair or remeshing.

## Scene lifecycle

- **Subsystems.** Each scene part registers with a registry ([subsystem.js](../src/scene/subsystem.js)) as an object with optional `applyQuality`, `resize`, `update` and `dispose` hooks; a missing hook is a no-op. Hooks run in `lifecycleOrder`. Disposal runs in reverse registration order, continues past a failing subsystem and rethrows the first error. A throw during initialization disposes what was registered, and nothing registers after disposal.
- **Borrowed resources.** A subsystem that derives from another's geometry, materials or programs restores the originals before freeing its own: the film terrain over the procedural ground, the lantern mount over the stand-in lantern, and the slate's shader hooks over the materials they extend. Quality changes and failed or stale loads keep a usable fallback.
- **Shared uniforms.** Some uniform objects are lent rather than copied, so one write reaches every material that reads them; a borrower never frees or replaces them ([Contracts](CONTRACTS.md#shared-uniform-objects)). index.js creates the slate's contacts and text boxes (`groundContacts`, mud-ground.js `createSlateContacts()`) before the sky shell and shares them with the ground, the rocks, the bark (`textGuard`), the sky shell and, through the shell, the stars. The starfield borrows the shell's `uTime`, `uFilm`, `uClouds`, `uNebulaLayers`, `uCloudReshape`, `uVortex`, `slateText` and `slateAspect`; disposing the stars leaves the sky and its uniforms intact. drifting-mist.js lends its `MIST_UNIFORMS` (with the ground's text boxes, `lendMistText()`) to every material the mist reaches.
- **Asset leases.** architecture-assets.js loads the tree, lantern and rocks for the startup tier, and commits the watch (no model) once its stage is ready; hill-silhouette.js loads the three massifs at the same tier through its `loadArchitectureAsset` (fetch priority `low`), outside the leases, and owns their maps until it is disposed; if one fails or misses `MASSIFS.deadline` (12 s), the requests abort and the five procedural rings land instead. A decoded asset is held by a lease through staging, commit and restoration; aborted or stale results are released through the same path. The watch and the tree are required. The tree's parsed asset passes through `architecture.js` `prepareArchitecture()` before these synchronous commit callbacks run. It imports the lazy `architecture-prepare.js` helper after parsing and prepares geometry in bounded tasks; a failed import preserves the synchronous constructor. A private WeakMap holds each prepared geometry and, for the tree, the original and softened normal buffers; the unchanged constructors consume that record and own its disposal. Aborting preparation frees partial geometry. The lantern and rocks are optional and never hold the reveal.
- **Reveal.** Until a directed shot is ready the hidden canvas keeps the pre-reveal orbit camera and redraws only when invalidated. Programs link through `KHR_parallel_shader_compile` (`createShaderWarmup`, each warm-up bounded at 2 s). For the real renderer, `shader-programs.js` queues compilation and snapshots every retained program variant for its materials, then polls those captured programs with a bounded wait that stops on disposal or context loss. It does not follow mutable material properties after a quality change or resource release. `rendering.compileShaders()` awaits scene colour programs, shadow-depth variants prepared on detached geometry probes, and the compositor. The compositor prepares scene copy, bloom, grading and final-pass programs in groups for their real render targets, with no added draw; its readiness promise is cached until context loss. Depth materials stay owned by rendering until disposal so the shadow program cache retains their leases. Completed mountains enter the same bounded warm-up before their first visible draw; their entrance fade starts with drawn frames, and a quality change during preparation keeps its current visibility rules. Before the reveal nothing draws while a warm-up is pending, and the reveal waits for it. The first frame that can show marks `babel:reveal`, adds `is-ready` to `#home-scene` and starts the 480 ms fade-in. Afterwards a committed model stays hidden until its programs are linked.
- **Framing.** Each directed shot is fitted inside a safe area cut from the hero's layout box and the bottom bar's top edge ([cinematic.js](../src/scene/cinematic.js) `cinematicSafeArea`). `isStackedLayout(width, height)` ([directed-shots.js](../src/scene/directed-shots.js), re-exported by cinematic.js for index.js) mirrors the hero's breakpoints in styles.css ([Contracts](CONTRACTS.md#hero-breakpoints)): a stacked layout frames the subject below the name; landscape phones and desktops frame it right of the hero; portrait monitors frame it across the full width above the name. `resolveDirectedShot` gives a shot its viewport variant ([Scene modes](SCENE-MODES.md#viewport-variants)): `portrait` for canvases taller than wide, stacked layouts and squat landscapes (up to 500px tall and narrower than `SQUAT_LANDSCAPE`, 1.55:1), unless a shot has its own `squat` variant for those; on letterboxed desktops (`letterboxShare` above 0) a shot's own `letterbox` variant comes first; for other canvases up to 500px tall, `compact` under 600px wide (The watch) or `landscape`; none elsewhere. index.js applies the film's phone text band only in a stacked layout.
  The late terrain's root-shading probe uses the same bounded program helper through the internal rendering owner's `compilePrograms` member, keeping that helper out of the lazy chunk's imports. Terrain also checks the renderer's material-property store identity, so a context loss and restore between polls invalidates the old probe. A restored context prepares a fresh probe before the shading's commit point. Each detached material stays owned until its bounded poll settles and the ground's first draw takes its program lease; terrain teardown removes its draw hook and releases the probe.

- **Commit points.** A change that would pop mid-shot lands only before the reveal, inside the fade-in, on a tour cut under the dissolve's kept frame, or on a still frame while the tour is not running: the lantern, the rocks, the film terrain, the slate's root shading and adaptive quality steps (`createDeferredQualityStep`, waiting at most 30 s). The mountains fade in instead. While the walk holds the tour, its own cuts in and out are the tour's (index.js `liveView`).
- **Coastal terrain.** film-scene.js keeps its borrowed ground while the lazy terrain owner prepares the coastline. On the live scene's `prepareOnly` path, `preparedEarthSteps()` extends the existing terrain slice scheduler with `coastGeometrySteps()`: cliff columns and stack rows prepare off-scene before the terrain promise resolves. The detached terrain owns the resulting `{ cliff, stacks, tier }` record until `createCliff()` consumes those exact buffers and clears the record; cancellation or disposal frees anything not consumed. The cliff owner then owns their disposal. Synchronous builders retain their byte-identical output, and no map or shader begins during geometry preparation. Terrain geometry, the slate shading, sea, cliffs, stacks, falls and `SEA_SINK` land together at an existing unseen commit point. `filmScene.ready` publishes the prepared height sampler; the cinematic reveal does not await it. Once the existing reveal, film, settled-tree and high/balanced gates permit rocks, rock-scatter.js starts its lazy module and the terrain promise independently. The builder starts both startup-tier GLBs without waiting for terrain preparation. Only placement waits for the resolved callable sampler and its own `ready` at the first coastal commit. Its internal `setActive()` hook withdraws the whole tuple when film deactivates and reuses its prepared resources at an eligible cut on reactivation. Its height delegates to procedural ground and its shore distance becomes infinite until landing and while withdrawn, so walking follows the visible surface. Rock placement takes its stable `film` sampler instead: later GLB completion cannot seat permanent rocks against the withdrawn procedural surface. The scatter owner immediately observes both the terrain promise and its eventual readiness, even if its lazy import fails or disposal wins. The builder owns completed model resources while waiting, aborts pending requests on disposal, releases late/completed sources once, and suppresses late failure status after disposal. Program preparation and the existing cut-only rock commit still follow placement. Disposal restores borrowed geometry, retires pending program polls, resolves uncommitted coastal readiness as false, and frees the derived shore resources.
- **Coast detail.** The lazy cliff owner borrows the ground's complete material for the shelf and owns its face/stack material. `coast-detail.js` creates independent optional owners for a shared 512px sRGB albedo (77,902 bytes, a 96 KiB streamed-body limit) and a shared 256px packed `NoColorSpace` normal/roughness tile (48 KiB limit). Each has an 8 s deadline and requests only after reveal; neither holds the cinematic reveal or waits for the other. The albedo is divided by its measured linear RGB mean and clamped to relative reflectance before mixing with the calibrated rock colour. Both textures reach the near-coast ground's uniforms (the material's `coastRockUniforms`) as the cliff's own bind and withdraw: exposed shelf bedrock takes the rock's colour and its detail normal in place of the soil's relief, in two turned lookups (`COAST_BEDROCK`), blending into slate soil inland; RG normal X/Y and B roughness remain data. Each owner stages its result until a tour cut or a still frame, leaves procedural shading usable on failure, and adds no pass or light. Withdrawal resets its own bindings and aborts pending work, while decoded textures and bitmaps remain cached for reactivation and context restoration. Adaptive steps reuse both fixed assets. Disposal withdraws the bindings before freeing each owned texture and bitmap; the borrowed ground material and its maps are never freed by the cliff, and the terrain restores the ground's previous uniform binding on teardown.
- **Holds.** Nothing on the page holds the scene; only a visitor pause, reduced motion and the walk do. `scene.setVisitorPaused()` holds the tour (a tour hold) and, from the reveal, rendering (a render hold, the scheduler's `"visitor"` hold, `createVisitorHold`); `scene.isVisitorPaused()` reads it. Reduced motion holds the tour and the drift. The walk ([Scene modes](SCENE-MODES.md#walk)) holds the tour from its capture until its dissolve back ends (`cameraTour.update({ held })`), and a visitor pause or reduced motion ends a walk at once. The lazy walk owner also exits immediately when forced colours become active, restoring page visibility and releasing its mouse capture even before its first cut; disposal removes that media listener. Behind a visitor pause a resize, context restore or content change (model, map, shader, font) draws one still frame; scroll never does.
- **Failure.** If the watch's stage fails or the tree cannot load, `failToTitle()` stops the scene at once (a host never shown is hidden; a shown canvas fades back to the title card) and disposes the runtime on a later tick, once in-flight warm-ups settle. There is no fallback world. A lantern failure keeps the stand-in lantern: an iron post lantern that [architecture.js](../src/scene/architecture.js) builds in code beside the tree, not part of any model.
- **Diagnostics.** `?sceneDebug=1` publishes a read-only status object, `BabelSite.sceneDebug`; [Scene modes](SCENE-MODES.md) lists its fields. It also enables Three's shader error checks. Normal visits disable those diagnostic checks, avoiding r160's synchronous shader/program log queries at first use; shaders and rendering quality stay the same. There are no developer controls; the walk is the visitor's, unannounced, and never a debug camera.

## Rendering and quality

The scene runs on the high and balanced tiers only; the low tier keeps the title card. quality.js picks the startup tier: a data-saver request, 2 GB or less of device memory, or weak limits (textures under 4096 or anisotropy under 4) give low; four cores or fewer, a phone-sized touch viewport, a touch device without flagship limits, or a short side under 340 px give balanced; the rest get high. `?quality=` overrides it and pins the governor: an explicit tier takes no adaptive step.

|                     | High      | Balanced |
| ------------------- | --------- | -------- |
| Pixel-ratio cap     | 1.5       | 1.25     |
| Shadows             | 2048 map  | 1024 map |
| Bloom               | on        | off      |
| Scene MSAA (WebGL2) | 4 samples | none     |
| Stars               | 4200      | 2600     |

Touch-primary devices cap the pixel ratio at 1.25 on every tier. The composer's targets follow the canvas in device pixels; the renderer's own antialiasing is off. Star sprites, bloom and the ink contour are sized in CSS pixels. Models and slate maps keep the startup tier (`assetTier`), so a quality step never re-downloads them. The optional coastal albedo and packed detail tiles are fixed at 512px and 256px respectively on both live tiers and never re-download on an adaptive step.

The governor samples display intervals only after the reveal, and not for 3 s after a resize, resume, context restore, pause release or asset commit; a dissolve's tour capture, cut and first blended frames are skipped. A 60-frame window averaging over 20 ms for 120 consecutive frames steps down one tier. A revealed scene never draws the low profile: its step below balanced, the resolution step, keeps the profile and lowers only the pixel ratio to 1. Recovery needs 300 frames whose window average stays under the larger of 15 ms and 1.1 times its 10th percentile, counted only while that percentile is at most 17.5 ms (a display at 60 Hz or faster that keeps up), and 10 s since the last change; each recovery followed by another downgrade doubles both, and after two such oscillations recovery stops. While the tour runs, a step waits for the next cut; where the browser links programs in parallel, it links them first (`rendering.prepareQuality()`).

[runtime.js](../src/scene/runtime.js) renders only visible frames, on an even cadence: every nth vsync of the estimated refresh rate near 60 Hz (144 Hz draws 72 fps; touch screens stay at or below 60). The moon key's shadow map (`rendering.lights.sun`) redraws only after a shot, quality, resize, model or treatment change, or a restored WebGL context; a step between the tiers' map sizes frees the map for the next draw to allocate. The renderer uses `PCFSoftShadowMap`, whose directional-light filter in three r160 is a fixed 3×3 texel footprint that ignores `shadow.radius`, so the scene sets no radius: the map's texel size alone sets how soft a shadow's edge falls. The coast's own shaders read the same map: [ocean.js](../src/scene/ocean.js) `lighting()` lends its texture and matrix per draw (`seaShadow()`, a 16-tap bilinear PCF that fades in before the map's edge), the cliffs and stacks cast into it, and each of the fault's shots centres the film's shadow camera on its rock (`COAST_SHOTS` `shadow`). Before the watch commits, [night-environment.js](../src/scene/night-environment.js) prepares its environment while models download: it awaits the sky program, allocates the pinned r160 PMREM generator's blur material through its `_setSize` and `_allocateTargets` hooks, and awaits the blur and background programs before the unchanged `fromScene()` capture. Real renderer polls snapshot the program objects rather than r160's mutable material properties, stop on disposal or context loss, and time out after 2 s per link phase; a timeout leaves the established on-demand capture available. CompileAsync-only adapters retain their polled resources until the underlying operation settles. The watch's stage awaits `environment.ready`, so film activation borrows a finished capture. Its sky shader, cube size and filtering are unchanged; rendering.js recaptures after a lost context ([below](#sky-stars-and-far-plain)). The window's `resize` and a ResizeObserver on the host feed the resize controller (runtime.js `createSceneResizeController`), which resizes the renderer with `setSize(width, height, false)` when the size or the pixel ratio changed. A pixel-ratio change that resizes nothing, such as a window moved to a display of another scale, reaches it through runtime.js `createPixelRatioWatcher()`: index.js wires it to the controller, and it listens to a `(resolution: <ratio>dppx)` media query, re-arms on the new ratio after each change, then calls the controller. `disposeHomeSceneRuntime()` removes its listener. Without `matchMedia`, or a query without `addEventListener`, it watches nothing. rendering.js checks the WebGL context before entering the composer, so a lost context is caught before Three.js hears of it. The page normally opens two WebGL contexts, the probe and the renderer, both with `powerPreference: "default"`. When the probe could not read the texture limits, the scene opens a third, short-lived one for them (quality.js `readWebGLQualityCaps`). The capability probe normally runs in the worker; the renderer stays on the document thread. Each probe releases its context through `WEBGL_lose_context`.

### Materials and grade

The live film keeps the sky's displayed palette and painted cloud treatment. [postprocess.js](../src/scene/postprocess.js) reads the existing alpha classifications: sky 0, mountains 1/3, ground 2/3 and subjects 1. Only sky takes cel quantization and ink; the star/glow mask excludes luminous surfaces, and ink also requires bare-sky neighbors. The lit layers (codes from 0.2: mountains, ground, subjects) carry scene-linear light: the grading pass takes it through the film's tone curve (`filmTone()`, [film-light.js](../src/scene/film-light.js) `FILM_TONE`: exposure anchored so a display level of 0.3 stays where it was, the camera's balance and night's saturation, a luminance Hill curve x^p/(x^p+k), the sRGB encode) on the shared `uTone` uniform (`FILM_TONE_UNIFORM`, assigned after the ShaderPass clones its uniforms); the sky and the star keep their colours as shown, and the 0.75 highlight shoulder is the sky's alone. The night sky's environment capture is untoned (`FILM_UNTONE_GLSL` in [night-environment.js](../src/scene/night-environment.js)), so the materials take the sky in scene light. Bloom's high pass divides the lit layers' luminance by `BLOOM_LIT` (the scene light the curve shows at 0.9, over 0.9), so only lights bloom. The painted dissolve uses the same nearest-layer cross from each frame, only where both classify as bare sky. Other layers dissolve continuously with the existing soft boundaries and subject/gap handling. Photographic grain, halation and lens effects remain in the existing passes. The shot's focus (`setLens()`) blurs in the final pass from the same codes: the sky and ranges by the shot's radius, the ground by a thin lens's circle of confusion from the plain's depth along each pixel's ray (its inverse affine in UV, `uGround`, with the kept frame's copy for the dissolve), with no depth buffer or pass. Three's color management stays off and its renderer tone mapping at `NoToneMapping`; the curve is the grading pass's, with no extra pass. The renderer keeps r160's legacy lights; [architecture.js](../src/scene/architecture.js) patches `lights_pars_begin` once so a decay-2 point light (the film lantern alone) falls off with the inverse square of its distance (`LANTERN_REACH`).

[architecture.js](../src/scene/architecture.js) keeps borrowed maps and UVs, matte timber roughness 0.9 and full timber normal strength. Tree normals use 0.75 strength, and its roughness map retains local variation within 0.82–1.00, with separate wet-bark, mud and moss regions. Role weights borrow the existing PMREM capture: timber ambient/sky/reflection [0.85, 0.55, 0.35], bark [0.7, 1.8, 0.85], rocks [0.6, 2, 1.8]. Non-lantern subject clones clear emission colour, intensity and maps, including any supplied self-illumination; film and quality changes never add bark emission. Subject edges use the existing lights and physical material response. Shot moods set no rim or pale state and never recolor bark or add a Fresnel diffuse rim. The lantern keeps its authored PBR response and the scene adds no light.

Each mountain GLB carries three material textures in standard slots: sRGB albedo in the base-color slot, an object-space normal map, and a `NoColorSpace` occlusion texture whose R channel is ambient occlusion and G is snow coverage. [hill-silhouette.js](../src/scene/hill-silhouette.js) validates the layout metadata, reads all three in the existing massif shader and normalizes albedo by its measured linear mean before applying continuous moonlight, occlusion and atmospheric haze: the scene's own key and sky light (`MOUNTAIN_LIGHT`, kept from its lights each draw) and Beer-Lambert haze by distance (`MOUNTAIN_AIR`), with a JS mirror of the rock body (`mountainBody()`) for the tests. Snow's light response is continuous, with its existing normal smoothing and coverage rules. The mountain owner keeps the textures and decoded images until disposal; a failed or late set retains the procedural range fallback.

The water programs share `rapidsGlsl()` between the ground and the falls, including the same flow clock. Wandering standing crests use analytic phase gradients for their reflected slopes and local wavelength filter; bank waves stay separate. Falling channels use broader current clusters with matched variance as finer detail fades, and adjacent streams aerate at different depths without disconnecting the head. Sea foam and reflections use the displaced surface near the camera, blending back to the level-plane projection only at the existing raised far rim. Within the plunge's existing support, backwash reduces only generic shore coverage and its far mean before the unchanged impact and stack contributions are combined; an absent pool and the outer coast retain their shading. The surf at the rock follows the swell's own phase there (`surgeGlsl()`: the arriving crest's age and the second swell's height), one surge along the shore and one for the nearest stack. The sea's mirror meets each stack's leaning waterline ellipse and a plane for the falls (`seaSheet`) analytically along the reflected ray and shades only the strongest hit.

The main film river has a physical bed and a separate upper cap in the existing ground geometry/material draw. `RIVER_CHANNEL` sets a 3.28-unit centre depth, current 3.2 units/s and 0.65-unit freeboard; freeboard eases in over the lantern plane's 14–28-unit band and respects root, lantern and puddle keeps. `rapidsSpeed()` shares the travel-time speed law: the channel shoals by discharge toward a 1.64-unit lip at 6.4 units/s, matching the falls' launch. The classic `RIVER.flow` remains its existing fallback value; the new film cap uses `RIVER_CHANNEL.speed`. The builder refines and constrains the wet bed, clips the cap against its actual bank intersections and uses wet-bed polygons through tight bends to avoid offset-strip folds. Refinement, carving, cap construction and attribute installation yield through the terrain's existing cooperative scheduler, with runtime ceilings of 78,000 solid and 8,000 water triangles. The height index samples only solid bed triangles, never the upper cap, so walking keeps its existing landing physics and clearance. The cap's clearness is per channel (`RIVER_CHANNEL.absorb`). The shared ground material receives `slateRiverSurface` mask/depth data and `slateShade` (`ROOT_SHADE`'s sky, key and lamp occlusion); the borrowed cliff shelf receives neutral zeros. The same terrain owner commits, withdraws and disposes the combined geometry.

The falls' geometry is a closed indexed solid: 816 vertices and 1,560 triangles on both tiers, with separate front/back positions, rounded side bands and paired strip caps that follow the folded profile without overlapping a concave fan. One `FrontSide` material renders the existing falls mesh in one draw. Its three-component `aFall` carries across-flow position, downstream travel and depth, so the same filtered current continues over its lateral faces; the fragment shader does not discard the walls. The upper run extrudes below its water surface, then its depth turns outward and narrows with ballistic velocity and bounded aeration. The terrain lends the complete upper-surface datum as `height.water`; `riverRunStart()` gives both the cap and the falls the same 15 joining points, and `riverShelfLift()` supplies their shared shelf correction. A standalone height sampler without `water` keeps the established shelf-height fallback. The upstream cap duplicates only its boundary normals, so its vertical closure cannot tilt the joining water surface into a false ridge; positions remain welded and the whole body is opaque with depth testing and depth writes. The single geometry and material stay under the existing coastal commit, withdrawal and disposal owner; no extra asset, light or render pass is introduced.

## Sky, stars and far plain

- **Sky shell.** [estate-sky.js](../src/scene/estate-sky.js) builds the shell's material, `createEstateSkyMaterial(config, textGuard)`. [atmosphere.js](../src/scene/atmosphere.js) drives its drift clock (`uTime`, on scene time) and its octaves (`uNebulaLayers`: 3 on high, 2 on balanced, 0 outside the film), and [film-scene.js](../src/scene/film-scene.js) turns `uFilm` on. The film's cloud field is GLSL text, `cloudFieldGLSL(time)`, which the shell interpolates and the stars evaluate too. Its reshaping, `CLOUD_RESHAPE`, works through two weights, both exactly 0 over the reference banks. The open weight (`open`, on the bank density) also leaves the roof's clear lane alone. The bend weight (`bend`, on the noise's coordinates) eases in over azimuths at least as wide and a wider radius, and also reaches the lane, which keeps its own clearing. Through `bend` the reshaping decompresses the noise toward the horizon, enlarges it evenly (`scale`) and swirls it; through `open` the half-frequency octave decides bank or clear sky, and the next octave cuts darker lanes inside the banks. Behind the name and intro the text guard (`CLOUD_TEXT_GLSL`) takes density off the reshaped banks, which the stars read too, so they burn off along their own contours; it reads the `slateText` and `slateAspect` objects that index.js lends as `textGuard`. `uCloudReshape` scales the reshaping: 1 for the shell and the stars. The vortex (`CLOUD_VORTEX`) turns the banks about the star where the lens sees it on the cloud plane (`uVortex.xy`, which index.js sets from the shot's lens on each cut and refit with `cloudVortexCenter()`): its weight takes the reshaping's wedge and radius, so it is exactly 0 over the reference banks, and `uCloudReshape` scales it too; it turns the cloud plane's point (`bv`, `b` itself where the turn is 0) about the eye, by an angle of the distance from it alone, so it never folds the noise, out to a reach that stops short of the reference banks for this eye (`uVortex.z`, `cloudVortexReach()`), before the reshaping maps it to the noise, a fixed spiral, and adds log-spiral arms that turn rigidly on the drift clock, a clearer eye and an optional ring to the density, taking nothing behind the text. In The watch (`guardShots`, `uVortex.w` 1) the star's disc and glow keep the sky behind them as it was, since the bloom they feed spreads into the reference banks, and the disc leans away from them.
- **Lightning.** [lightning.js](../src/scene/lightning.js) runs a seeded schedule on its own clock (scene time while the scene animates; nothing under reduced motion) and only in film, and only in the months of `LIGHTNING.months` (October), by the visitor's date when the scene starts; out of season it builds no bolt and never flashes. A flash is placed once, from the camera, when it first lights, and a cut ends it. It writes the shell's `uFlash`, `uFlashGlow`, `uFlashTone` and `uFlashCore`, which estate-sky.js draws in the banks (exactly 0 over `FLASH_REFERENCE`, The watch's crop), and film-light.js `FLASH_UNIFORMS`, the flash's light that every lit film material adds after its own lights through `flashHook()` (composed onto materialFor()'s, the lanterns' and the growth's onBeforeCompile, before `#include <aomap_fragment>`) and the slate through its own shader: light from the flash's side (the cool fill's for a flash in view), a share of the sky's and the flat light, with no view-dependent diffuse rim and none of it behind the text (`lendFlashText()` lends the ground's boxes at its creation). It also brightens the ground's sky light and water (`FLASH_GROUND`) and the drifting mist (`MIST_UNIFORMS.mistFlash`), away from the text. It never changes a scene light. Its one mesh, the bolt, draws at the far plane behind the ranges with max blending and the star's layer mark; a tall bolt keeps its size at whichever of the flash's places it fits, and only then tries shorter ones (`bolt.fallback`). Its one mesh, the bolt, draws at the far plane behind the ranges with max blending and the star's layer mark. Every value returns exactly when the flash ends.
- **Stars.** [starfield.js](../src/scene/starfield.js) borrows the shell's uniforms (`uTime` as `uSkyTime`, and `uVortex`) and takes the shell's radius (`WORLD.SKY_DOME_RADIUS`) from index.js. In film each star finds where its view ray leaves the shell, evaluates `cloudFieldGLSL("uSkyTime")` there, with the text guard at the star's own clip position, and dims by the bank's opacity in the sky (0.94). No sprite draws under `STAR_MIN_FOOTPRINT` (2 device px); its colour scales by the area ratio, so its light is unchanged.
- **Environment capture.** night-environment.js clones the shell's material for its one capture and gives the clone its own `uCloudReshape` (0, which also turns the vortex off), its own `uFlash` (0: no lightning flash) and an empty `slateText`. The capture keeps the clouds as authored, so the materials' sky light and reflections keep their approved brightness, and no text box from the page reaches the cube.
- **Far plain.** Past the film terrain's edge (`TERRAIN_EDGE`, 192 units from the origin, half of [filmic-earth.js](../src/scene/filmic-earth.js) `EARTH.width`) the frame shows the ranges' lower bodies below eye level (the near massifs' and, between them, the backdrop rings'; the near ring's when the five rings stand in). [hill-silhouette.js](../src/scene/hill-silhouette.js) eases that body, through a rocky skirt whose line rises and falls along the ring (`HORIZON_SKIRT`, up to 0.05 of slope about eye level), into the far plain's air: `TERRAIN_HORIZON` lifted by `HORIZON_AIR.horizon` (1.65) at eye level, rising to `HORIZON_AIR.edge` (1.9) where the view meets the terrain's edge. The feet haze to the same air over `HORIZON_HAZE`. [far-fires.js](../src/scene/far-fires.js) sets small warm fires out there (`FAR_FIRES`): one additive, depth-tested `Points` draw under the ground's root, each fire on the film terrain's height inside its edge or the far plain's level beyond it. A fire beyond the edge eases toward the ranges' ground line (`RANGE_MIST_SHAPE.floor`, since the ranges ride on the lens) and draws at most `haze.draw` units away along its ray, in front of the ranges' compressed depth and behind every nearer surface; the air dims and reddens it by its true distance, the shot's mist (`RANGE_MIST`) veils it, and so does the drifting mist ([drifting-mist.js](../src/scene/drifting-mist.js) `MIST_KEEP`: what `mistOver` keeps of a light at the fire, on the lent `MIST_UNIFORMS`, at `haze.drift` of its depth); its core and halo stay under the bloom's threshold with the mist's own light (`mistOver` over the plain's air) behind them. It goes out behind the text (the borrowed `slateText`, `slateAbout`, `slateAspect`), about the tree's silhouette (bands of its meshes' boxes, projected each frame, measured again when its meshes change) and in a shot's kept-clear rect (The watch's reference clouds). [mud-ground.js](../src/scene/mud-ground.js) darkens the slate's far edge toward `TERRAIN_HORIZON` times `HORIZON_AIR.ground` (1.75) and never lightens it, so the edge meets the far plain without a dark seam; ground shading stays continuous.
- **Drifting mist.** [drifting-mist.js](../src/scene/drifting-mist.js) adds no pass or mesh: `mistHook()` composes onto a built-in lit material's onBeforeCompile and replaces `#include <fog_fragment>` with the fog followed by `mistOver()`, which gathers the mist's optical depth along the lens's ray to the fragment, below the mist's ceiling only, in a few steps (`mistFrame`: 4 on high, 2 on balanced, none on low) of drifting 3D value noise, and lights it by the moon key, its moonlit side and the star. materialFor() (the tree, the rocks), the lantern's frame and candle and the growth material (grass, litter, rushes) take the hook; the slate (mud-ground.js) and the ranges (hill-silhouette.js `MIST_RANGES`, along their view ray to the plain, only up to a little above eye level) call `mistOver()` themselves. Its uniforms (`MIST_UNIFORMS`) are lent to every material; index.js lends the ground's text boxes, sets the moon and the star, and each frame the shot's share (`setMistShot()`, 0 outside the film), the plain's datum and the drift clock (`advanceMist()`, held for reduced motion and a visitor pause).

## Build pipeline

[build.mjs](../build.mjs) writes `dist/` through [tools/build-output.mjs](../tools/build-output.mjs), which stages the payload, replaces assets before HTML and rolls back if publication fails.

- **Scripts.** The scene builds as ESM with code splitting: the entry, one shared chunk that may hold only third-party code (the build refuses a first-party module there, since it would evaluate before the entry's ordered imports), and lazy chunks. Chunks are named after the hash of their final bytes, dependencies first, so any change yields a new entry URL. The capability worker builds next as an independent IIFE. The UI then builds as one IIFE that names the worker URL and the entry's static chunks for preloading. The scene entry receives the model and slate manifests as string literals (`__BABEL_ARCHITECTURE_URLS__`, `__BABEL_MATERIAL_URLS__`); the UI receives only each tier's tree URL and size. The separate scalars `__BABEL_COAST_MATERIAL_URL__` and `__BABEL_COAST_ALBEDO_URL__` are read only in the lazy coastal chunk, keeping both optional URLs out of the entry and the slate manifest.
- **Fingerprints.** Scripts, CSS, every model, the slate maps, both coastal material maps and the fonts publish only as `name.HASH.ext` (eight hex digits of SHA-256), immutable for a year. The fonts are discovered from `fonts/*.woff2`. The stylesheet's font `url()`s are rewritten before minifying, from LF bytes, and the pages' asset paths (the stylesheet, the scripts and the font preloads) with exact replacements; an un-hashed stylesheet, script or font path, or a `?v=` query, left after the rewrite fails the build.
- **Legal comments.** esbuild keeps license comments at the end of each output (`legalComments: "eof"`); the shared chunk ends with Three.js's notice.
- **Shader compaction.** [tools/shader-compact.mjs](../tools/shader-compact.mjs) strips indentation, comments and spaces beside punctuation from the scene's GLSL template literals before esbuild minifies; Three.js's own shaders are untouched.
- **Static files.** The hosting, icon and discovery files in `public/` are copied verbatim (`public/site-agents.md` becomes `/AGENTS.md`); `sitemap.xml`'s `lastmod` comes from `public/index.md`'s `dateModified`. `fonts/OFL.txt` publishes beside the fonts.
- **Development.** `npm run dev` ([tools/dev.mjs](../tools/dev.mjs)) watches the inputs ([tools/watch.mjs](../tools/watch.mjs)), serializes rebuilds and serves `dist/` through an owned Wrangler process. Watch builds pass `--retain-assets`, which keeps, for pages already open, the hashed scripts, CSS, images, models and fonts that the folder's previous build recorded in its manifest (`.cache/build-outputs/`); without it a build removes the files its predecessor recorded and it no longer writes, and a file no build recorded is never removed. A failed build keeps the last good output. `--outdir` writes elsewhere than `dist/`; build-output.mjs `validateOutputDirectory` refuses the project root or any folder containing it, `src`, `images`, `fonts`, `public`, `tools`, `test`, `node_modules`, `.git`, `.cache` or any folder inside them, a path through a symbolic link, and an existing file, and `publishBuild` refuses a non-empty folder other than `dist/` that is not an earlier output of this project.

## Tests

`npm test` runs `node --test "test/*.test.mjs"`: Node's own runner, no framework. Files are grouped by domain: page and UI (`markup-accessibility`, `hero`, `contact`, `scene-loader`, `boot`, `webgl-probe`), scene wiring (`scene-bootstrap`, `scene-basics`, `scene-runtime`, `scene-quality`, `scene-postprocess`, `scene-visitor-pause`, `startup-cost`), camera (`cinematic`, `framing`, `coast-framing`, `camera-tour`, `opening-star`), subjects and surroundings (`architecture`, `architecture-preparation`, `architecture-assets`, `lantern`, `sky`, `night-environment`, `hill-silhouette`, `mountain-massifs`, `lightning`, `film-scene`, `ground`, `terrain-build`, `ocean`, `coast-detail`, `coast-geometry`, `coast-material`, `coast-waterfall`, `river-channel`, `rock-startup`, `coast-preparation`, `coast-handoff`), delivery (`build`, `bundle-output`, `hosting`, `smoke-pages`, `workflows`), and the docs (`docs`). `bundle-output` builds the site once into a temporary folder under `.tmp-preview-review/` and checks the real payload; two of its tests build small fixture projects there as well (the refused shared chunk, and a changed model's effect on the UI bundle).

[test/support/](../test/support/) holds shared helpers, outside the test glob. Each of `code.mjs`, `css.mjs` and `html.mjs` has its own whitespace-normalizing `flat()` for its language, so source, style and markup checks survive formatting; `code.mjs` also reads source files, and `css.mjs` parses rules and media blocks and computes contrast. `glb.mjs` is a GLB reader that handles normalized integer attributes, byte strides and node transforms, `terrain.mjs` holds the plain-dune baseline the terrain tests compare against, `ground.mjs` the live scene's analytic ground for the framing fixtures, and `contact-dom.mjs` is the fake footer the contact and boot tests run contact.js over.
